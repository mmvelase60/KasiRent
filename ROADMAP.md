# KasiRent roadmap

This is a proposed sequence, not a promised schedule. The current local MVP is documented in the [release baseline](docs/18-Release-Notes/KR-REL-001-Initial-Local-Baseline.md).

| Stage | Focus | Exit evidence |
| --- | --- | --- |
| Current | Rooms, historical tenancies and move-outs, effective-month rent changes, rent charges, payments, corrections, text receipts | Existing source and limited local test/build results |
| Next: ledger completeness | Missing-charge indicators and opening adjustments | FR-013 and FR-017 acceptance tests; migrations on populated data |
| Pilot preparation | Stable receipts, account recovery, privacy operations, exports and restoration | FR-014–FR-016 and physical-device checks |
| Controlled pilot | Reconcile real workflows over two rent cycles | Recorded user feedback and balance agreement |
| Public release | Hosting, monitoring, hardened access and recovery | Release-readiness gates closed with evidence |
| Later | Tenant portal, maintenance, reminders and documents | Separately accepted requirements and operating responsibility |

See [user stories](docs/02-Requirements/KR-USR-001-User-Stories-and-Acceptance-Criteria.md), [risk register](docs/00-Governance/KR-RSK-001-Risk-and-Decision-Register.md) and [release gates](docs/12-Deployment/KR-DEP-001-Deployment-and-Release-Readiness.md). No public deployment or additional feature implementation is performed by this documentation change.
